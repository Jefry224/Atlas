# Mission Dossier scenario and request isolation

The integrated baseline `79138b6` allowed a late terrain response to replace the selected scenario's evidence. The coordinator reproduced this by delaying Wright Valley's DEM by 1200 ms, selecting `polar-shadow`, and selecting `hyperarid-salt` 30 ms later: the selector showed the salt scenario while the evidence summary showed Wright Valley and Shackleton. The status also claimed that Modules 2 and 3 were included while both summary rows were unavailable. The original receipt is [race-before.json](race-before.json).

The targeted repair changes only `dossier.js`, adds `dossier-session.mjs` and focused tests, and records evidence in this directory. Other changes visible in the shared working tree belong to their respective workers. The [earlier integration audit and acceptance matrix](integration-audit.md) describe the baseline before this repair; their remaining findings are separate work.

`createDossierSession` owns a selection revision and separate loading/generation requests. Selecting any scenario immediately clears the previous context, document, errors and busy state; aborts superseded requests; and gates generation until matching evidence is ready. Every late success, error and cleanup checks ownership, including when a transport ignores abort. The loader captures one scenario throughout DEM, weather and process work, verifies its candidate, and publishes the context atomically. The Generate request receives a copied context, and a completed document retains the requesting scenario ID for its Markdown filename. A failed terrain load leaves no generatable context. Optional absent or malformed forecast data remains unavailable while valid terrain and audit context can still be used.

The evidence summary and readiness status use the same actual module availability. They no longer promise a 72-hour analysis when only absent or incomplete forecast data was supplied. Endpoint bodies and provider configuration are unchanged; this repair does not implement the separate provider-context budgeting, active Earth mission context or execution-report handoff discussed in the audit.
